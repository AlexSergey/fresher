# 024/03/03 — The UI

**Status:** 🔨 in progress · **Version:** 0.1.0 · **Date:** 2026-11-21 · **Modules:** app/ui

The interface's path for the module (plan 027 removed module pages and module sidebar entries): Scan's danger-zone
cards of its two categories and the category Details screen with the left-out lines, the review, the cleanup and put back, the settings with the Node switch off
by default, the notice when access to Documents is missing. No new component: titles, reasons and the switch are the
core's texts and settings. The design: [`../00-design.md`](../00-design.md), section 9.

## Files

- `app/ui/src/test/unused-toolchains-scan.ts` (new) — a scan as the core streams it: the module `unused-toolchains` in
  the group `development` with its two categories (`Rust 1.70.0-aarch64-apple-darwin` and `Rust
  nightly-2023-06-01-aarch64-apple-darwin` Low, `Node v12.22.12` Medium), one left-out (`pin-unknown` on a Node
  version; never an item both offered and left out), the two switches (Node off). A second script: the categories
  unavailable for want of Documents. Texts read from `modules/unused-toolchains/locales/en.json`, shared by the unit
  tests and the e2e mock. Only states the core can produce together.
- `app/ui/e2e/core-mock.ts` — the scans as the mock's scripts (`unusedToolchains`, `unusedToolchainsNoDocuments`).
- `app/ui/e2e/flows.spec.ts` — the scenarios, negatives first:
  - negative: "a Node version kept for an unreadable pin cannot be selected"; "without access to Documents the unused
    toolchains categories say what they need";
  - positive: "unused toolchain versions show on Scan with their size"; "each unused toolchains category
    shows its danger and its four texts"; "a toolchain's finding names the version, the date and the command";
    "selecting a Node version makes the review name Medium"; "a Rust toolchain goes to the Trash and comes back";
    "Settings shows the Node versions switch off by default".
- `app/ui/e2e/visual.spec.ts`, `axe.spec.ts` — the category Details screen and Scan's cards.
- `app/ui/e2e/screenshots/` — the new images, looked at before committing.

## Conclusions

Built on plan 027's UI: no module page and no sidebar entry, so the module's categories are shown on Scan in
their danger zones and on the category Details screen, as plan 023 did. The mock keeps a Node version left out as
not-yours, because the core cannot offer a Node version and leave another out for an unreadable pin (that reason
blocks the whole row). The Node switch is on in the main script, the default-off check runs on the no-Documents
script, and the module has four texts, not five. The visual and axe loops now wait for Select all; that changed the
local-ai-models details baseline, which had been captured before the list loaded, and it was regenerated and looked
at.
