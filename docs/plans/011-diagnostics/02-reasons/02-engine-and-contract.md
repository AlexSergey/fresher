## Files

- `crates/engine/src/session.rs` — `Output::left_out` adds the left-out into a per-module map keyed by (category,
  reason), at most one entry per declared key and category, so the map is bounded by the descriptor. A reason the
  module did not declare is still counted (the user learns why anyway) and logged once per key at `warn` as a bug. At
  the module's end the map becomes `ModuleFinished { left_out }`, also when the module failed or was cancelled (what
  it left out before is true). A panicking module's left-outs are kept like its findings.
- `crates/engine/src/testing.rs` — the test module can report left-outs (`on_finish` already takes the sink).
- `crates/testing/src/run_module.rs` — the harness collects into a recording sink; `ModuleRun::left_out:
  Vec<LeftOutItem>`. `golden()` adds `leftOut` only when it is not empty, so every existing golden report stays as it is.
- `crates/testing/src/contract.rs`:
  - `check_module_contract`: every declared problem has a text (`MissingText`); no template of the module's
    dictionary names `{detail}` (`ContractProblem::DetailInSentence { key }`).
  - `check_texts_used`: a run's failure reason and every left-out reason must be declared
    (`ContractProblem::UndeclaredProblem { key }`); declared problems count as used, so a failure text no run hits is
    not an `UnusedText`.
- `modules/trial/src/lib.rs` — declares its one failure text, `trial.error.failed`; nothing it offers changes.
- `modules/demo/src/lib.rs` and its `locales/en.json` — declares `demo.error.failed` and `demo.left-out.open`
  ("The app that made it is open. Quit the app, then scan again."); `finish` reports one left-out of a made-up
  item in `demo.caches` (one per scan, a fixed size), so a development build shows the line.

## Conclusions

Built (de36209, fix dc47f85). `crates/engine/src/left_outs.rs` sums per (category, reason) in a sorted map, one per
module through a `ModuleSink`, so a left-out belongs to the module that reported it; they are sent for every outcome.
A left-out outside the module's own categories is dropped with a once-only warning and refused by the contract
(`ForeignLeftOutCategory`); an undeclared reason is counted and warned once. The contract gained `UndeclaredProblem` and
`DetailInSentence`, and a declared key counts as used. Demo declares `demo.error.failed` and `demo.left-out.open` and
reports one made-up left-out of 157,286,400 bytes per scan; trial declares `trial.error.failed`. The core e2e goldens
changed (every `module-finished` has `leftOut`): they had been red since 02/01, and were regenerated and reviewed. The
sandbox goldens are unchanged. Design call 4 stands, reworded: left-outs are event-only, so after a restart no
left-out line shows until the next scan (the restore runs before the UI subscribes; its events are not replayed). A
left-out of a category in the scan's ignore list is not counted (final review). The text `trial.error.failed` had no
next step; 03/01 added one.
