# 002/05/01 — Generated TypeScript types

**Status:** ✔️ done · **Version:** 0.1.0 · **Date:** 2026-11-15 · **Modules:** app, app/ui

## Files

- `app/tauri/Cargo.toml` — dev-dependency `ts-rs` (workspace), dependencies on `fresher-core`.
- `app/tauri/tests/bindings.rs` — renders the declarations of every type the IPC carries (`Event`, `CommandError`, the
  command inputs and outputs and everything they contain), in a fixed order, with a header "generated by
  `app/tauri/tests/bindings.rs`, do not edit", into one string; compares it with
  `app/ui/src/ipc/bindings.generated.ts`; `UPDATE_BINDINGS=1` rewrites the file (reviewed in the diff, like the golden
  files). The exact `ts-rs` 12 API for rendering a declaration to a string is checked here.
- `app/ui/src/ipc/bindings.generated.ts` — the generated file (committed; never edited by hand).
- `app/ui/src/i18n/types.ts` — the hand-written `Text` and `TextArg` replaced by imports from the generated file.
- The lint configs exclude `*.generated.ts` where they need to (Prettier formats it after generation, so the test
  formats in the same way or compares after Prettier: the step picks one and writes it in the test's doc comment).

## Produces

The types 05/04 imports; the stale-types check of the acceptance.

## Checks

- Negative: `the_bindings_file_is_up_to_date` fails after a field is added to `Finding` without regenerating (checked
  once by hand, written in the plan's conclusions).
- Positive: the same test passes on the committed file; `npm run lint:ts` passes with the generated types imported.

## Notes from the implementation

- **The file is `ts-rs`'s output as it is, never formatted**: `*.generated.ts` is in `.prettierignore` and in ESLint's
  ignores, and knip ignores it in `app/ui` (unused exported types are not an issue of a generated file). The test
  compares byte for byte; Prettier is not run on it.
- `ts-rs` 12 renders a declaration with `T::decl(&Config::new())`; the test writes each one as `T::docs()` (the Rust
  doc comment as JSDoc) + `export ` + the declaration, which is what `ts-rs`'s own export does for one file, without
  the per-file imports. One file holds every type, so no imports are needed.
- The list is in a fixed hand-written order (the event, the error, the commands' outputs, then what they contain).
  Two more checks keep it whole: `no_type_refers_to_a_type_left_out_of_the_file` (every `T::dependencies()` of a
  listed type is listed, none twice) and `no_number_becomes_a_bigint`.
- `app/ui/src/i18n/types.ts` takes `Completeness` and `Dictionary` from the generated file too, not only `Text` and
  `TextArg`: they were the same hand-written copies. `TextArgs` (the chrome's args) stays.
- `fresher-core` is a normal dependency of the app from this step (the commands of 05/02 use it); `ts-rs` a
  dev-dependency.
- Checked by hand: a field added to `Finding` without regenerating fails `the_bindings_file_is_up_to_date`.
- Prettier finds `.prettierignore` in the folder it runs from: `npx prettier --write src` run inside `app/ui` formats
  the generated file (it happened once during 05/04 and was regenerated). Run Prettier from the repository root, as
  the hooks do; the staleness test catches it otherwise.
