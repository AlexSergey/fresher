## Notes from the implementation

- **The core changed (the main session's decisions)**: `SettingsView` gains `file: SettingsFile` (`loaded`,
  `newer-version`, `broken`, `unreadable`), so the UI knows whether the settings are read-only and why;
  `SettingsFile::is_read_only()` is true for `NewerVersion` and `Unreadable`. The enum moved from the engine to the
  core, and `Engine::settings_file()` is gone: `Engine::settings().file` answers it. The text of
  `core.error.settings-read-only` names both causes. No texts for the four states yet: the settings screen is plan 005.
- **Before this step, its own commit** (`fix(engine)`): a settings file that could not be read (`StoreError::Io`) is
  read-only, never saved over, so a passing read error cannot replace the user's values with the defaults.
- **The core dictionary in front**: `Registry::new()` starts its dictionary with `core_dictionary()` and so returns
  `Result<Self, RegistryError>` (new variant `CoreDictionary`); `Default` is gone. Module keys cannot collide with the
  core's: the id `core` is reserved.
- **Files**: the adapters (`SystemClock`, `ProcessCommandRunner`, `UnknownAccess`, `NoWalk`) are in
  `app/tauri/src/adapters.rs`, the wiring in `compose.rs` (`engine(data_folder)`, `registry()`), the commands in
  `commands.rs`, the tests' shell in `testing.rs` (`Shell`: a mocked Tauri app, `tauri::test::mock_app`, managing an
  engine over the app's real modules with a temporary data folder, `FakeClock` and a walk that finds nothing or holds
  until cancelled). `tauri`'s `test` feature is on for the dev-dependency only.
- **The commands** run with `#[tauri::command(async)]`, off the main thread (a settings save `fsync`s). They take
  `State<'_, Engine>`; `get_findings` takes `query`, `update_setting` takes `update`, `get_dictionary` takes `locale`
  (a string, parsed by `Locale::parse`), `subscribe` takes `channel`. `get_modules`, `get_access_status` and
  `app_version` return their value without `Result` (they cannot fail; Clippy refuses a needless `Result`).
  `#![expect(clippy::needless_pass_by_value)]` on the file: Tauri passes the state and inputs by value (`docs/hacks/`).
- **`subscribe`** spawns one thread, `fresher-events`, that forwards every event of a bus receiver until the channel
  refuses a message or the engine is dropped. A reloaded page subscribes again; the old thread ends at the first
  refused send.
- **The app manifest**: `build.rs` holds `COMMANDS`, passed to `tauri_build::AppManifest::commands`; `main` returns the
  build error instead of panicking. `tauri-build` writes `permissions/autogenerated/*.toml` on every build: ignored by
  git. The capability lists `core:default` and `allow-<command>` (kebab-case) for each command.
- **The tests read the files**: `tests/config.rs` compares `generate_handler!` in `src/lib.rs`, `COMMANDS` in
  `build.rs` and the capability, and checks that no plugin permission but `core:default` is granted.
- **Data folder**: `compose::engine` opens Tauri's `app_data_dir()` with `DataFolder::open` (created `0700`), in the
  `setup` hook; a failure stops the app with the error.
- `fresher-module-demo` is an unconditional dependency (Cargo has no `cfg(debug_assertions)` dependencies); its
  registration is `cfg(debug_assertions)` (`docs/hacks/`).
- Not done here: `npm run tauri dev` was not tried: the agent cannot open a window. The UI's smoke e2e passes.
- **Fixed after review**: each `subscribe` started a thread that never ended (a send to a reloaded page's channel did
  not fail). Now one `EventForwarder` (`src/events.rs`, managed next to the engine) runs a single `fresher-events`
  thread; a new `subscribe` replaces the channel, a refused send drops it. `ProcessCommandRunner` (`src/process.rs`)
  kills a program after `COMMAND_TIMEOUT` (60 s; spawn, poll `try_wait`, kill and reap) and drains its pipes on threads;
  the `CommandRunner` port takes no cancel token, so a run cannot be cancelled before its timeout, and a timeout is
  reported as `Failed` (the port has no variant for it). The capability grants no core permission any more:
  `core:default` (path, event, window, webview, app, image, resources, menu, tray) was unused. The UI calls only the
  app's commands, a JS `Channel` is a callback (`transformCallback`, no IPC), and `plugin:__TAURI_CHANNEL__|fetch`, which
  carries large channel messages, is exempt from the ACL in Tauri 2.12.5 (`webview/mod.rs`); closing the window is
  native. Lost with it: the dev-only devtools hotkey (⌘⌥I calls `plugin:webview|internal_toggle_devtools`); the
  context menu's "Inspect Element" still opens them. `tests/config.rs` checks that no `core:` or plugin permission is
  granted.
