## Conclusions

Built: `ollama-scan.ts` (a scan, a download scan, modules, totals), the scripts `localAiModelsOllama` and
`localAiModelsOllamaDownload`, six flow scenarios (negatives first), a visual and an axe spec of the category Details
and the confirm dialog with the other files listed, four new baselines (chromium and WebKit). The mock states only what
the core can produce: sharing is symmetric (the derived model's sharer is named, a third model has none), a model's tags
are in name order with the first tag's manifest as the subject, identities are `ollama/<host>/<namespace>/<model>/<tag>`,
and the shared mock now declares the module's four categories. The shared reason is a hidden row description and never
on screen, so the visual asserts "Select all" and the reason is asserted in the flows. Known flake: the chromium
baseline `category-details-app-leftovers-chosen` rewrote itself under one `--update-snapshots changed` run; reverted,
the plain run passes. Review: needed fixes (mock categories, identities), fixed in round 1 and re-reviewed.
