# 030/02/03 — The UI

**Status:** 🔨 in progress · **Version:** 0.1.0 · **Date:** 2026-11-21 · **Modules:** app/ui

The interface's path for the module: Scan's card for its category and the category's Details with its findings and
left-out line, the review, a cleanup that empties, put back, the settings switch. No new component: a
finding's title and reason are the core's texts, and the emptied outcome is shown by the cleanup's detail row since plan
008 (the result summary counts what went to the Trash). The design: [`../00-design.md`](../00-design.md), section 7.

  `system` with its category (`Editor`, `Editor: com.example.Editor.Helper`, `Player: com.example.Player.ShipIt`, Low,

## Conclusions

Built with the existing card and Details screen, no new component. The mock states three findings and one app-open left-out; the cleanup mock empties the folders. The "Emptied. The folder itself stays." text shows in the cleanup detail row of an item with no trashed entries (F3), not in the result line, which reads "Moved 2 items to the Trash". Review fix: `reportOf` counted an emptied outcome into both the moved and the deleted sizes; it now counts it once by method (a unit test pins it). The after-cleanup overview is outcome-based in the engine, so an emptied folder that skipped an entry is still removed from the results, and the mock says so.
