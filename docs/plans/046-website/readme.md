# 046 — The website, getfresher.app

**Status:** 🔨 in progress · **Version:** 0.2.0 · **Date:** 2026-11-27 · **Modules:** site, ci, docs

A one-file plan with the recommended decisions taken. Asked by the user on 2026-11-27: the domain `getfresher.app` is
bought and served over HTTPS by the hosting; the design of the landing page was approved from the mockup ("in general
the design will do"); the user chose a cookieless visit counter, a `/download` link of its own, the version kept in
the disk image's name, and the deploy in CI with the hosting's credentials in the repository's secrets.

## Goals

1. **The landing page** from the approved mockup ("v2 — calm and rich"): what Fresher finds (all kinds, by danger
   level, from `docs/categories/`), the confirmation, the principles, the install, the first launch. Static HTML and
   CSS, no build step, no framework, no third-party font or script but the counter.
2. **`/download`**: a small page that counts the visit and sends the browser on to the disk image of the latest
   release (`Fresher_<version>_universal.dmg`), so one stable link serves the site, the README and posts. It is made
   by CI from the latest release; nothing is edited by hand at a release.
3. **Counting visits and downloads** with GoatCounter: no cookies, no personal data, so no consent banner. The site
   counts page views and the clicks of the download links; GitHub counts the real downloads of each asset.
4. **Deploy in CI**: a workflow uploads the site to the hosting over SFTP (FTPS if the hosting has no SFTP) on a push
   to `main` that changes the site, on a published release (a new `/download` target), and by hand.

## Decisions taken (recommended, 2026-11-27)

- The site lives in `site/` at the repository's root: its own small folder, code like the app's, listed in the
  repository map.
- `/download` is a page, not a server redirect: it is counted by the counter and does not depend on the hosting's web
  server reading `.htaccess`. With scripts off, a `<meta http-equiv="refresh">` still sends the browser on.
- The counter's site code is a public value in the site's files (it is shown in every page anyway); the hosting's
  host, user, password and folder are repository secrets, never in a file.
- The upload tool is installed from the runner's package manager, not a third-party action; it is listed in
  `docs/dependencies.md`.
- Plain FTP is never used: it sends the password in the clear.
- FTPS (explicit TLS, the certificate checked) is the default, SFTP the other choice (`SITE_PROTOCOL`): the hosting's
  SFTP is tied to its main account, so the site uploads with an FTP user locked to the web root, checked by hand on
  2026-11-27 (TLS 1.3, a certificate that verifies). The job runs in the GitHub Environment `site`, from `main` only.
- The site names no other product; the tools the app cleans may be named (the categories' own names).
- The app's own privacy promise is unchanged: the app makes no network requests. The privacy doc says the website,
  not the app, counts visits without cookies.

## Steps

1. The site's pages and styles in `site/`, from the mockup; the kinds of files from `docs/categories/` (generated by a
   script, so the site never drifts from the catalogue), placeholders where a value is not known yet.
2. `/download`'s page made from the latest release by a script; its tests.
3. The deploy workflow; its secrets documented; the release steps in `docs/release.md` mention it.
4. Docs: the repository map (`CLAUDE.md`, `docs/restrictions/repository.md`), `docs/dependencies.md`,
   `docs/restrictions/privacy.md`, the README's link to the site.
5. The user's look: the site on `https://getfresher.app`, a click on Download, the counter's dashboard.

## Open for the user

- The GoatCounter site code (the user registers it; the agent does not sign up with the user's email).
- The hosting's SFTP host, user, password and folder, put into the repository's secrets by the user.
