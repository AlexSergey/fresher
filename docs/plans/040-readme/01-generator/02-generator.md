# 040/01/02 — The table's generator and check

**Status:** 🔨 in progress · **Version:** 0.1.0 · **Date:** 2026-11-22 · **Modules:** scripts

A repository script that builds the README's "What it finds" block from `docs/categories/` and either writes it
(`npm run readme:generate`) or checks that the README holds exactly that (`npm run check:readme`). Not wired into
`pre-push` yet (02/01 does it, once the README has its markers). The design: [`../00-design.md`](../00-design.md),
sections 2 and 5.

## Context

- Repository scripts are TypeScript files in `scripts/`, run by Node 24 directly (`node scripts/x.ts`, type stripping;
  no build), kebab-case file names (ESLint `check-file`), tested with `node:test` and `node:assert/strict` by
  `npm run test:scripts` (`node --test scripts/*.test.ts`). Model the style on `scripts/check-staged.ts` and its test:
  exported pure functions, `readonly` types, the entry under `if (import.meta.main)`, errors to `stderr` prefixed with
  the script's name, `process.exitCode`.
- Tests: `describe('<function>')` → `describe('negative cases')` first, then `describe('positive cases')`;
  descriptive names; deterministic; never read the real `docs/` or `README.md` (strings, or a temporary folder from
  `fs.mkdtempSync(path.join(os.tmpdir(), 'fresher-readme-'))`, removed in `after`).
- 01/01 gave every category file a `**Example:** <text>` line after its header line.
- `docs/categories/README.md` has a "## Danger levels" table (`| Level | Meaning | Examples |`, the level written
  `**Safe**`) and a "## Catalogue" table (`| Category | Danger level | Rule | File |`, the file written
  `` [`x.md`](./x.md) ``). Some rows are aligned and some are not; parse cells by splitting on `|` and trimming.
- `README.md` is formatted by Prettier at commit (`.lintstagedrc.cjs`, `*.md`; config `.prettierrc`, `printWidth`
  120). The generator must produce what Prettier keeps.

## Files

- `scripts/readme-catalogue.ts` (new) — pure functions, no file system, no Prettier:

  ```ts
  export type Danger = 'High' | 'Low' | 'Medium' | 'Safe';
  export const DANGERS: readonly Danger[] = ['Safe', 'Low', 'Medium', 'High'];

  export type ProblemKind =
    | 'bad-example' | 'danger-mismatch' | 'duplicate-row' | 'markers' | 'missing-file'
    | 'no-example' | 'no-levels' | 'no-title' | 'stale-block' | 'unlisted-file';
  export type Problem = { readonly kind: ProblemKind; readonly where: string; readonly message: string };

  export type CatalogueRow = { readonly category: string; readonly danger: string; readonly file: string };
  export type Category = {
    readonly category: string; readonly danger: Danger; readonly example: string;
    readonly file: string; readonly title: string;
  };
  export type Levels = ReadonlyMap<Danger, string>;

  export const MAX_EXAMPLE_LENGTH = 80;
  export const START_MARKER =
    '<!-- what-it-finds:start — generated by `npm run readme:generate` from docs/categories; do not edit by hand -->';
  export const END_MARKER = '<!-- what-it-finds:end -->';

  export const parseCatalogue = (catalogueReadme: string): readonly CatalogueRow[];
  export const parseLevels = (catalogueReadme: string): { readonly levels: Levels; readonly problems: readonly Problem[] };
  export const readCategories = (
    rows: readonly CatalogueRow[],
    files: ReadonlyMap<string, string>, // file name (`dev-caches-npm.md`) → text, README.md excluded
  ) => { readonly categories: readonly Category[]; readonly problems: readonly Problem[] };
  export const buildBlock = (categories: readonly Category[], levels: Levels): string;
  export const replaceBlock = (readme: string, block: string): { readonly text: string } | { readonly problem: Problem };
  ```

  - `parseCatalogue`: the rows of the first table after the line `## Catalogue`, header and separator skipped; the
    category is the first cell without backticks, the danger the second cell, the file the link target of the fourth
    cell without `./`.
  - `parseLevels`: the "Meaning" cell of each row of the first table after `## Danger levels`, keyed by the level
    without `**`; a level of `DANGERS` missing → one `no-levels` problem naming it.
  - `readCategories`, one problem per finding (the refusals of the design's section 2): `missing-file`,
    `unlisted-file` (a key of `files` no row names), `duplicate-row` (a category or a file twice), `no-title` (no
    line starting `# `), `danger-mismatch` (the file's first word after `**Danger level:**` is absent, not one of
    `DANGERS`, or not the row's), `no-example` (no line starting `**Example:**`, or nothing after it), `bad-example`
    (over `MAX_EXAMPLE_LENGTH` characters or holding `|`). `where` is `docs/categories/<file>`. Categories keep the
    catalogue's row order.
  - `buildBlock` returns, joined with `\n`, ending without a newline:

    ```markdown
    Fresher knows **<N> kinds** of files, each with a danger level:

    - **Safe** — <meaning>
    - **Low** — <meaning>
    - **Medium** — <meaning>
    - **High** — <meaning>

    | What | Where, for example | Danger |
    | --- | --- | --- |
    | [<title>](docs/categories/<file>) | <example> | <danger> |
    ```

    Rows sorted by `DANGERS` order, then by the catalogue's order (a stable sort). `<N>` is the number of categories.
  - `replaceBlock`: exactly one `START_MARKER` line and one `END_MARKER` line after it, else a `markers` problem
    (`where: 'README.md'`); otherwise the text with everything between them replaced by `\n\n<block>\n\n`.

- `scripts/readme.ts` (new) — the entry and the only file-system and Prettier code:

  ```ts
  export type Mode = 'check' | 'generate';
  export const formatMarkdown = async (text: string, filePath: string): Promise<string>;
  export const run = async (mode: Mode, root: string): Promise<readonly Problem[]>;
  ```

  - `formatMarkdown`: `prettier.resolveConfig(filePath)` and `prettier.format(text, { ...config, filepath: filePath })`
    (`import * as prettier from 'prettier'`; Prettier 3 is already a devDependency).
  - `run`: reads `<root>/docs/categories/README.md` and every other `*.md` there, `<root>/README.md`; builds the
    block; formats `replaceBlock(...)`'s text with `formatMarkdown(text, '<root>/README.md')`. `generate`: writes it
    when there is no catalogue problem (a catalogue problem writes nothing). `check`: a `stale-block` problem when the
    formatted text differs from the file. Returns every problem.
  - Entry (`import.meta.main`): `mode` from `process.argv[2]` (`generate` or `check`, anything else: a usage line and
    exit code 2), `root` = `path.resolve(import.meta.dirname, '..')`; each problem printed as
    `readme: <where>: <message>`; on `stale-block` the message ends "run `npm run readme:generate`"; exit code 1 when
    there is a problem.

- `scripts/readme-catalogue.test.ts` (new) and `scripts/readme.test.ts` (new) — the tests below.
- `package.json` — scripts `"readme:generate": "node scripts/readme.ts generate"` and
  `"check:readme": "node scripts/readme.ts check"`, kept in the file's alphabetical order. Not in `pre-push` yet.

## Tests

`scripts/readme-catalogue.test.ts`, on strings:

- Negatives, one per refusal: a row whose file is not in the map (`missing-file`); a file no row names
  (`unlisted-file`); a category twice and a file twice (`duplicate-row`); no `# ` line (`no-title`); the danger line
  missing, `**Danger level:** Severe`, and `Low` against a row's `Safe` (`danger-mismatch`); no example line, and
  `**Example:**` with nothing after it (`no-example`); an 81-character example and one with `|` (`bad-example`); a
  levels table without `High` (`no-levels`); a README with no marker, with two start markers, and with the end
  before the start (`markers`).
- Positives: `parseCatalogue` on a table with one aligned and one unaligned row; `buildBlock` on two categories (one
  `Low` listed first, one `Safe`) gives the exact text above with `Safe` first; an 80-character example is accepted;
  `replaceBlock` changes only the text between the markers (the lines before and after are kept byte for byte).

`scripts/readme.test.ts`, on a temporary folder with `docs/categories/README.md`, two category files and a `README.md`
with the markers:

- Negatives: `check` on a README whose table cell was edited returns `stale-block`; `generate` with a category file
  missing its example returns `no-example` and leaves `README.md` unchanged.
- Positives: `generate` then `check` returns no problem; running `generate` twice gives the same bytes;
  `formatMarkdown` aligns an unaligned two-row table the way Prettier does (compare with `prettier.format` called
  directly).

## Produces

`run`, `formatMarkdown`, `Problem` and the markers, for 01/03 (which adds the link check to `run`) and 02/01 (which
adds the markers to the README and wires `check:readme`).

## Checks

- `node --test scripts/readme-catalogue.test.ts scripts/readme.test.ts` passes; `npm run test:scripts` passes.
- `npm run lint:ts`, `npm run lint:code` (ESLint over the scripts), `npm run knip`.
- `node scripts/readme.ts check` on the repository reports only `markers` for `README.md` (the README has no markers
  until 02/01) and no catalogue problem.
- Commit: `feat(repo): generate the README's category table from the catalogue`.

## Conclusions

Done (abe63079). `scripts/readme-catalogue.ts` (pure: parse, build, replace the block) and `scripts/readme.ts` (file
system and Prettier's own API with the repository's config, so the pre-commit hook never reformats the block);
`npm run readme:generate` and `npm run check:readme`. Changed from the design: when the catalogue has problems,
`generate` writes nothing and `check` does not compare the block (no `stale-block` noise on top of the real problem);
the example's length is counted in UTF-16 units. A second row naming a repeated category no longer also reports
`unlisted-file`.
