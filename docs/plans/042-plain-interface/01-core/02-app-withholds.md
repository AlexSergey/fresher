# 042/01/02 — The app withholds High

**Status:** 🔨 awaiting the user's walk · **Version:** 0.1.0 · **Date:** 2026-11-24 ·
**Modules:** core, app/tauri, sandbox, testing, app/ui (mocks and bindings), docs

The app sets `HighLevel::Withheld` for the normal engine and for sandbox mode, in every build; the sandbox autotest
offers High except in one case file that proves the withheld app offers nothing High; the app's info reports the
switch to the UI. The design: [`../00-design.md`](../00-design.md), section 1; agent's calls 1 and 18.

  too, so the walk sees what ships).
- `app/tauri/src/sandbox.rs` — `SandboxMode` gains `high: HighLevel`, `Withheld` from `new` and `from_env`; `pub fn
  offering_high(self) -> Self` (for the autotest only; doc comment says so); `compose` passes it into `Shared`.
- `app/tauri/src/testing.rs` — the test app's engine: `HighLevel::Offered` (unchanged behaviour).
- `crates/core/src/app_info.rs` — `AppInfo { version, build, high: HighLevel }`; `app/tauri/src/commands.rs` —
  `app_info` reads `engine.high_level()` (`State<'_, Engine>`); its test asserts `high`.
- `crates/sandbox/src/case.rs` — a top-level key `high = "withheld"` (any other value refused with the file's parse
  error, naming the key); `CaseFile::high() -> HighLevel` (`Offered` when absent).
- `app/tauri/tests/sandboxes/harness.rs` — the mode is `SandboxMode::new(...).offering_high()` unless the file says
  `high = "withheld"`; for such a file the harness also asserts that no finding, total or storage-map "Explained" holds
  a High item, whatever its cases say.
- `fixtures/sandboxes/high-withheld.toml` (new) — `feature = "high-withheld"`, `module = "app-leftovers"`, `high =
  "withheld"`; negative first: the data folder of a removed app (High) is not offered; positive after: the caches of
  the same removed app (Safe) are offered and go to the Trash. Model the tree on `app-leftovers.toml`'s cases; its
  golden report written as the other case files' are (`docs/testing.md`, "Sandboxes").
- `crates/sandbox/src/expected.rs` — in a file without `high`, a positive whose danger is High gets the line "Not
  shown in the app: High is withheld in this release." (the app always withholds); a test in its `mod negative` /
  `mod positive` blocks. Regenerate every `EXPECTED.md` the generator writes (`npm run sandbox -- <feature>` is by
  hand only; the generator's own tests cover the text).
- `app/ui/src/ipc/bindings.generated.ts` (regenerated by the bindings test), `app/ui/src/ipc/mock.ts`,
  `app/ui/e2e/core-mock.ts` and every UI fixture that builds an `AppInfo`: `high: 'offered'` (the mocks state what the

- `docs/testing.md` — "The case file": the `high` key; "Sandboxes": every case file runs with High offered but one

## Conclusions

- `compose.rs` and `SandboxMode` set `Withheld` in every build and mode; `offering_high()` is the autotest's only way
  to offer. `AppInfo.high` reports it (`HighLevel` added to the bindings here).
- The case file's `high = "withheld"` (any other value refused with the parse error); the harness checks a withheld
  file for no High finding or total and "Can be freed" equal to the found size; `EXPECTED.md` says "Not shown in the
  app: High is withheld in this release." under a High positive of an offering file.
- `high-withheld.toml` (`com.example.Withheld`): the support folder (High) is the user's folders on the map, the caches
  (Safe) are offered. With the harness forced to offer, the file fails, as it must.
